Ordering System · GCP blueprint · Section 1

Identify the resources: run every piece through six questions

Don't start from the GCP product list. Start from what you already run: your docker-compose.yml and K8s/ folder. For each piece, ask what it does. The answer tells you which kind of cloud resource it needs. Watch the sorting machine, or click any piece.

What you already have
The question that matches
Does it run code?→ Compute: a place for containers to run
Does it keep data after a restart?→ Storage: disks or a managed database
Does it talk to the internet or other pieces?→ Network: VPC, load balancer, IPs
Does someone or something need permission?→ Identity: service accounts and roles
Is it an artifact we build and store?→ Supply chain: registry, state bucket
Does it help us see what's happening?→ Observability: logs and metrics
GCP resource we pick
GKE cluster + node poolRuns every Deployment and StatefulSet from K8s/
Persistent Disk (via PVC)Postgres, RabbitMQ and Seq data. Cloud SQL later.
VPC + subnet (+ LB later)Pod/Service IP ranges. Ingress creates a load balancer.
Service accounts + rolesNodes, GitHub Actions, you. Workload Identity Federation, no keys.
Artifact Registry + GCS bucketContainer images; Terraform state file.
Seq in-cluster + Cloud LoggingCloud Logging is on by default (50 GiB/month free).
